# Security policy (preview)

**No security-response SLA or formal vulnerability bounty currently exists.** Please **do not** publish vulnerabilities, exploitation steps involving real secrets, user files, or credentials in public Issues.

Until the maintainer has enabled GitHub's private vulnerability reporting or provided a dedicated secure contact, avoid posting sensitive exploit details; mention only that a private report is available. The maintainer should enable **Settings → Security → Private vulnerability reporting** as part of the public launch checklist.

Do not assume experimental downloads or API use are safe for sensitive work. Rotate any exposed credentials and preserve your backups.
